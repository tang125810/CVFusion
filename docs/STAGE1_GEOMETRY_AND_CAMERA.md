# Stage1 几何契约与相机贡献诊断报告

日期：2026-09-26
执行依据：《Stage1_四个参考项目的适用性与排查顺序_20260926.md》第 5 节第 2 步“几何与相机贡献诊断”。
范围：冻结权重、冻结数据，不训练、不改活动配置。所有脚本位于 `third_party/RadarPillar/experiments/stage1_audit_20260926/`。

## 1. 结论

1. **几何契约通过。** 四条可证伪检查全部通过：3D 框投影与标签 2D 框中位 IoU 1.000；落在 GT 3D 框内的雷达点有 99.97% 同时落在该目标 2D 框内；训练态增强闭环（撤销 `lidar_aug_matrix` 后再投影）命中率 90.8%/98.9%/95.9%；视角变换的单元几何（δ 深度 + 单像素）与独立 numpy 推导逐格一致，质量守恒相对误差 0。
2. **视角变换的有效覆盖只有约 30%。** 相机在雷达系中俯仰约 +6.3°、光心位于 `(0.05, 0.98, 1.44)`，检测体积竖直只有 5 m（z ∈ [-3, 2]）；96×152×64 的“像素×深度”假设中只有 **30.38%** 落在体积内，图像上半部几乎不贡献。这不是缺陷，而是“z-valid 过滤”在正确工作；但它决定了相机分支的有效感受范围。
3. **相机分支对当前模型是不可或缺的，且失效方式是候选召回崩塌。** 把图像换成常量帧后 Entire 3D mAP 从 52.27 掉到 **4.96**，Recall@0.25 从 58.40% 掉到 **9.47%**；换成随机噪声后 mAP 3.03、Recall@0.25 0.83%。这属于推理期分布偏移，**不能**当作 radar-only 精度。
4. **错帧图像只损失 4.0 mAP（Entire）、0.04 mAP（ROI）。** 说明模型对“图像与点云是否严格同帧”不敏感；相邻验证帧本就高度相似，因此这是一次弱扰动，不能据此推断相机贡献是纯几何的。
5. **图像消融的崩塌不是特征尺度问题。** 融合统计显示常量帧下相机 BEV 与融合特征的量级与正常帧同阶（|mean| 0.10 vs 0.09，fused max 38.4 vs 37.9），差异在空间结构而非幅值。
6. **附带发现：RGIter 的门控已饱和到 1.0。** 三个尺度的 `sigmoid(weight_conv(radar_bev))` 在正常输入下 mean=max=1.000，即论文式(4)(5)的“雷达引导加权”在训练后退化成了恒等通路，融合实际是 `concat(radar, camera)` 后卷积。此项列入第 5 步（RPN/雷达骨干核对）继续核。

## 2. 几何契约检查（400 帧，跨整个验证集等间隔抽样）

脚本：`verify_geometry_contract.py`，输出 `geometry_contract.json`。

### A. GT 3D 框 → P2 → 与标签 2D 框比 IoU

用原始标定（`R0`、`Tr_velo_to_cam`、`P2`）投影 8 个角点并取外接框，与标签 2D 框比较。

| 类别 | 样本 | 中位 IoU | IoU>0.5 比例 |
|---|---:|---:|---:|
| Car | 1269 | 1.000 | 0.883 |
| Pedestrian | 281 | 1.000 | 0.943 |
| Cyclist | 5 | 1.000 | 0.800 |

中位 IoU = 1.000 说明投影链、轴序、主点、尺度缩放全部正确；未达 0.5 的样本是截断/遮挡目标（投影外接框大于可见 2D 框）与出画目标，符合预期。

### B. GT 3D 框内的原始雷达点 → 是否落在该目标 2D 框内

| 类别 | 目标数 | 框内点数 | 同时落在 2D 框内 |
|---|---:|---:|---:|
| Car | 812 | 13920 | 0.9998 |
| Pedestrian | 210 | 1071 | 0.9972 |
| Cyclist | 3 | 116 | 1.0000 |

这条检查是独立于检测器的：它把“点云 → R0∘V2C → P2 → 标签”整条链一次性验证。前提已核实：`radar_5frames/training/calib` 是指向 `radar/training/calib` 的软链（雷达外参，平移 `(0.053, 0.981, 1.444)`），与 `lidar/training/calib`（平移 `(0.151, -0.461, -0.915)`）**不是**同一套外参，当前配置读取的是雷达那一套，符合数据实际。

### C. 增强闭环（训练态）

训练态样本中 `gt_boxes` 位于增强后的雷达系，相机分支用 `camera_to_lidar @ lidar_aug_matrix` 把相机射线送到同一坐标系。检查反向链：`inv(aug)` → `inv(camera_to_lidar)` → 缩放后的内参 → 是否落在（按 608/1936、384/1216 缩放的）标签框内。

| 类别 | 样本 | 框中心落在标签框内 |
|---|---:|---:|
| Car | 281 | 0.9075 |
| Pedestrian | 272 | 0.9890 |
| Cyclist | 123 | 0.9593 |

Car 的 90.8% 与检查 A 的 88.3%（IoU>0.5）同源，缺口来自截断/出画目标；闭环本身没有系统性错位。

### D. 视角变换单元几何

用真实标定实例化 `PaperRGIterFusion`，输入 one-hot 图像特征 + δ 深度分布，与独立 numpy 重推逐格比对：

- 三个“在体积内”样本：期望格与实测格**完全一致**（如 `[106, 77]`、`[140, 17]`、`[75, 237]`）；
- 一个“体积外”样本：实测为空，期望为空；
- 全图质量守恒：把 64 个深度概率均分到所有像素，输出总质量与独立统计的“体积内 (像素, 深度) 对数量 / 64”相对误差 **0.00e+00**。

同一检查给出了覆盖统计：`in_volume_pairs = 283714 / 933888 = 30.38%`。逐行看，图像上半部（feature row 0~30）几乎无有效深度假设，贡献集中在图像下半部。

**解释（对第 4 步的意义）：** 相机俯仰 +6.3°、光心在雷达系 z=+0.98 m，而检测体积只有 z ∈ [-3, 2]。水平以上射线在 15～20 m 处就穿出体积顶面，其后的深度假设全部被 z-valid 规则拒绝。因此“整幅图像 × 64 深度”里真正进入 BEV 的只有约三成，集中在图像下半部——这正是 LXL 式“体素中心反向采样”会改变覆盖率的地方（采样式实现按目标体素决定采样点，而不是按像素决定散射点）。

## 3. 相机贡献诊断（推理期消融）

脚本：`run_image_ablation.py`（只替换 `batch_dict['images']`，权重、后处理、NMS 完全不变），评分用《Stage1_评估对拍与旋转IoU核验》中的官方协议 + 精确 IoU。

| 模式 | Car | Ped. | Cyc. | Entire 3D R11 mAP | ROI mAP | Recall@0.25 | 平均框数/帧 |
|---|---:|---:|---:|---:|---:|---:|---:|
| none（基线） | 42.16 | 45.67 | 68.97 | **52.27** | 69.47 | 58.40% | 9.35 |
| zero（常量黑帧） | 9.09 | 5.79 | 0.00 | **4.96** | 3.03 | 9.47% | 3.54 |
| noise（随机噪声帧） | 9.09 | 0.00 | 0.00 | **3.03** | 3.03 | 0.83% | 5.07 |
| wrong_frame（上一帧图像） | 40.60 | 40.80 | 63.41 | **48.27** | 69.43 | 56.30% | 9.32 |

读法：

- 常量帧与噪声帧把**候选召回**打掉八成以上，说明相机分支主要作用在“产生候选”这一步，而不是只做后期加权；
- Car 在常量/噪声下都停在 9.0909（= 1/11，R11 的量化下限），说明几乎没有有效 TP；
- 错帧的 Entire 损失 4.0 mAP、ROI 仅 0.04，且召回只降 2.1 个百分点。相邻帧图像高度相似，所以这是弱扰动，不能推出“相机贡献是纯几何/纯纹理”的结论。

**边界声明：** 这三组都是推理期分布偏移实验。报告第 2 步已经指出它们不能替代 radar-only 重训；本报告的读数只用于判断“模型有多依赖图像”，不作为 radar-only 精度。

## 4. 融合统计（解释消融崩塌的性质）

脚本：`probe_fusion_stats.py`（3 个 batch，逐模式记录相机 BEV、门控、融合特征统计），输出 `fusion_stats.json`。

| 模式 | 相机 BEV \|mean\| | 相机 BEV std | 相机 BEV max | 融合 \|mean\| | 融合 max | 门控 mean |
|---|---:|---:|---:|---:|---:|---:|
| none | 0.0929 | 0.3828 | 163.30 | 0.0571 | 37.94 | 1.000 |
| zero | 0.1024 | 0.5354 | 203.74 | 0.0614 | 38.37 | 1.000 |
| noise | 0.2486 | 0.8576 | 206.70 | 0.1090 | 92.57 | 1.000 |
| wrong_frame | 0.0930 | 0.3837 | 163.32 | 0.0569 | 37.85 | 1.000 |

结论：

1. 常量帧并没有把相机 BEV 或融合特征推到训练分布之外（同阶量级），因此第 3 节的崩塌反映的是**内容/空间结构**缺失，而不是尺度爆炸；
2. 噪声帧的量级确实偏大（约 2 倍），可部分解释它比常量帧更差；
3. **门控饱和**：`sigmoid(weight_conv(radar_bev))` 三个尺度全部为 1.000，原始 logit 均值 **15.92**、最大 **64.01**（三个尺度、四种图像模式完全一致，因为门控只由雷达 BEV 决定）。当前融合等价于 `concat(radar_bev, camera_bev)` 直接卷积，论文式(4)(5)的雷达引导权重没有起作用。

## 5. 对后续步骤的输入

- 第 3 步（图像特征假设）：相机分支既然决定候选召回，图像特征层级就是高价值单变量；已在 `vod_cvfusion_paper_stage1_imgmulti.yaml` 准备“完整冻结 Swin-T + 多层聚合到 H/4”的候选（depth head、image_proj、VT、RPN、anchor 全部不变）。
- 第 4 步（VT 假设）：几何测试已通过，采样式 VT 已实现并通过独立验收（`verify_vt_sampling.py`：δ 测试逐格一致、形状与基线一致），配置 `vod_cvfusion_paper_stage1_vtsample.yaml`。
- 第 5 步（RPN/雷达骨干）：门控饱和、覆盖只有 30% 两项需要与高度压缩、稀疏下采样、anchor 覆盖率一并核对。

## 6. 复现命令

```bash
cd third_party/RadarPillar
conda activate cvfusion-paper

# 几何契约（400 帧等间隔抽样，A/B/C/D 四项）
python experiments/stage1_audit_20260926/verify_geometry_contract.py \
  --frames 400 --out experiments/stage1_audit_20260926/geometry_contract.json

# 采样式 VT 的独立几何验收（δ 深度 + 单像素，对照 numpy 推导）
python experiments/stage1_audit_20260926/verify_vt_sampling.py

# 推理期图像消融（四种模式各一遍，四卡并行）
for spec in 0:none 1:zero 2:noise 3:wrong_frame; do
  gpu=${spec%%:*}; mode=${spec##*:}
  CUDA_VISIBLE_DEVICES=$gpu python experiments/stage1_audit_20260926/run_image_ablation.py \
    --ckpt output/cfgs/vod_models/vod_cvfusion_paper_stage1_zvalid/paper_stage1_zvalid_v1/ckpt/checkpoint_epoch_78.pth \
    --mode $mode --batch_size 2 --workers 4 \
    --extra_tag ablation_image_$mode --eval_tag full
done
# 导出 + 官方口径评分见《Stage1_评估对拍与旋转IoU核验_20260926.md》第 7 节

# 融合统计
CUDA_VISIBLE_DEVICES=0 python experiments/stage1_audit_20260926/probe_fusion_stats.py \
  --batches 3 --device cuda
```

## 7. 未做与边界

- 未重训任何模型；消融全部是推理期扰动。
- 几何检查覆盖 400 帧（等间隔抽样整个验证集），不是全部 1296 帧；A/B/C 三项都是逐目标统计，样本量已在表中给出。
- 增强闭环只在训练态前向所用的同一套 `lidar_aug_matrix` 上验证，未覆盖 `random_world_flip` 单独分支的边界（配置中该增强已启用，抽样样本自然包含翻转与非翻转两种）。
- 覆盖统计（30.38%）用的是第 00000 帧标定；不同帧标定存在差异，但相机安装关系一致，量级不变。
